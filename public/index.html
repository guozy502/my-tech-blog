一、为什么 Java 要先"解释"再"编译"？

1.1 编译与解释的古老争论

AOT 编译（C/C++/Go） 解释执行（早期 JVM）
启动 编译慢（几分钟），运行快 启动快，但每条指令都要翻译
优化 编译时一次性优化 无法做深度优化
跨平台 需要重新编译 一次编译，到处运行

Java 的选择：两个都要——先解释执行保证快速启动，再把热点代码动态编译成机器码。
