一、底层结构——一个会变长的 Object[] 

public class ArrayList<E> extends AbstractList<E> {
    transient Object[] elementData;  // 真正存数据的地方
    private int size;                // 当前元素个数（不是数组长度！）
}

二、动态扩容——1.5 倍的生长策略 

// 核心扩容方法
private Object[] grow(int minCapacity) {
    int oldCapacity = elementData.length;
    if (oldCapacity > 0 || elementData != DEFAULTCAPACITY_EMPTY_ELEMENTDATA) {
        int newCapacity = ArraysSupport.newLength(oldCapacity,
            minCapacity - oldCapacity,   // 至少增长这么多
            oldCapacity >> 1);            // 优先增长一半 → 1.5 倍
        return elementData = Arrays.copyOf(elementData, newCapacity);
    } else {
        return elementData = new Object[Math.max(DEFAULT_CAPACITY, minCapacity)];
    }
}
操作 公式
默认扩容 newCapacity = oldCapacity + oldCapacity/2（1.5 倍）
不够时 直接扩到 minCapacity
超大数组 最大 Integer.MAX_VALUE - 8

一、BeanPostProcessor 接口——一切扩展的入口 

public interface BeanPostProcessor {
    // 初始化前回调
    default Object postProcessBeforeInitialization(Object bean, String beanName) {
        return bean;  // 可返回原始对象或包装对象
    }
    // 初始化后回调
    default Object postProcessAfterInitialization(Object bean, String beanName) {
        return bean;  // ← AOP 代理在此创建！
    }
}

核心设计：在 Bean 初始化的前后两个节点插入拦截逻辑。Spring 本身的大量功能（@Autowired、@PostConstruct、AOP、@Async）都是通过实现这个接口完成的。

ByteBuf 内存管理——引用计数、池化与零拷贝

Anonymous 发布于 2026-06-28 收录于 Netty

一、ByteBuf 的结构——比 ByteBuffer 好用在哪？ 

// ByteBuf 有两个指针：readIndex 和 writeIndex
// 0          <= readerIndex <= writerIndex <= capacity
// 已读区域    可读区域            可写区域

ByteBuf buf = Unpooled.buffer(16);
buf.writeInt(42);                    // writerIndex: 0→4
buf.writeLong(100L);                 // writerIndex: 4→12
int v = buf.readInt();               // readerIndex: 0→4, 返回 42
ByteBuffer ByteBuf
读写切换 需要 flip() 手动切换 双指针自动管理
扩容 固定容量 自动扩容
引用计数 ❌ ✅ release()/retain()
池化 ❌ ✅ PooledByteBufAllocator

二、引用计数——谁用谁 retain，用完 release 

// ByteBuf 默认引用计数 = 1
// 每次 retain() → refCnt++
// 每次 release() → refCnt-- → 归零时回收内存（池化则归还池）

ByteBuf buf = pooledAllocator.buffer();
buf.retain();   // refCnt = 2  （多一个地方引用）
buf.release();  // refCnt = 1
buf.release();  // refCnt = 0 → 归还池 / 释放

// 黄金法则：最后一个访问 ByteBuf 的 Handler 负责 release
// TailContext 会自动释放 inbound 消息（如果不是池化或没被 retain）

三、PooledByteBufAllocator——jemalloc 内存池 

// 池化分配器：避免频繁分配/释放堆外内存
ByteBufAllocator allocator = PooledByteBufAllocator.DEFAULT;
ByteBuf buf = allocator.buffer(1024);

// 内存池分层：
// Arena（线程绑定） → ChunkList → Chunk（16MB） → Page（8KB） → SubPage（<8KB）
// 类似 jemalloc 的设计：ThreadLocal 缓存 + 多级分配
配置 默认值
Page 大小 8KB
Chunk 大小 16MB
缓存线程数 CPU 核数
堆外/堆内 默认堆外（-Dio.netty.noPreferDirect=false）

四、零拷贝——CompositeByteBuf 

// 传统合并两个 ByteBuf：需要复制数据
ByteBuf merged = Unpooled.buffer(buf1.readableBytes() + buf2.readableBytes());
merged.writeBytes(buf1);
merged.writeBytes(buf2);  // 数据被复制了

// Netty 零拷贝合并：不复制，只存引用
CompositeByteBuf composite = allocator.compositeBuffer();
composite.addComponent(true, buf1);
composite.addComponent(true, buf2);
// composite 只是一个"视图"，内部 buf1 和 buf2 的数据没有被复制！

五、总结

机制 作用
双指针 readerIndex/writerIndex 分离，不用 flip
引用计数 release() 自动回收，retain() 增加引用
池化 减少堆外内存分配开销，提高吞吐
CompositeByteBuf 零拷贝合并多个 Buffer

一、inbound 和 outbound——两个方向 

// inbound：从 Socket 读到数据 → 从 Head 开始向 Tail 传播
// 触发链：channelRead → ctx.fireChannelRead(msg)

// outbound：写数据到 Socket → 从 Tail 开始向 Head 传播
// 触发链：write → ctx.write(msg)

public class MyHandler extends ChannelInboundHandlerAdapter {
    @Override
    public void channelRead(ChannelHandlerContext ctx, Object msg) {
        // 处理读到的数据
        System.out.println(msg);
        ctx.fireChannelRead(msg);  // ← 传给下一个 InboundHandler
        // 如果忘记调 fireChannelRead → 后续 Handler 收不到数据！
    }
}

二、ctx.write vs ctx.channel().write —— 关键区别 

// ctx.write()：从当前 Handler 开始向 Head 传播（只经过前面的 OutboundHandler）
// ctx.channel().write()：从 Tail 重新开始传播（经过所有 OutboundHandler）

// ❌ 错误：在中间的 Handler 用 channel().write() → 经过的 Encoder 可能重复编码
@Override
public void channelRead(ChannelHandlerContext ctx, Object msg) {
    ctx.channel().writeAndFlush(response);  // 绕过了当前之前的 Handler！
}

// ✅ 正确：用 ctx.write() → 按顺序经过前面的 OutboundHandler
@Override
public void channelRead(ChannelHandlerContext ctx, Object msg) {
    ctx.writeAndFlush(response);  // 正常传播给前面的 Encoder
}

三、ChannelHandler 生命周期

方法 时机
handlerAdded Handler 被加入 Pipeline
channelRegistered Channel 注册到 EventLoop
channelActive Channel 激活（连接建立）
channelRead 读数据到达
channelReadComplete 本次读完成
channelInactive Channel 断开
channelUnregistered Channel 从 EventLoop 注销
handlerRemoved Handler 被移除
