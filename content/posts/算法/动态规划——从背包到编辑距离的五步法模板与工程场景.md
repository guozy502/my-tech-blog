# 动态规划——从背包到编辑距离的五步法模板与工程场景

> 动态规划是算法面试的分水岭——它不是"记住几道题的解法"，而是"看到一个问题能识别出 DP 结构"。本文从统一的五步法模板出发，拆解背包、LIS、LCS、编辑距离四个核心模型，讲清楚状态转移方程的推导过程，以及 DP 在 diff 算法和推荐系统中的应用。

---

## 一、DP 五步法——从"看答案才懂"到"自己推出来"

DP 的核心难点不是写出转移方程，而是**先定义一个正确的 dp 含义**。五步法把思考过程标准化：

```
1. 定义 dp[i] 或 dp[i][j] 的含义
   → 这一步是最关键的。问自己：dp 数组的一个元素代表什么？
   
2. 推导状态转移方程
   → dp[i] 和 dp[i-1]、dp[j] 之间有什么关系？
   → 通常有两种选择："选/不选当前元素" 或 "当前元素和之前某个子问题组合"
   
3. 确定 base case
   → dp[0]、dp[-1]、dp[0][0] 应该初始化为什么？
   
4. 确定遍历方向
   → 正序遍历还是倒序遍历？
   → 如果 dp[i] 依赖 dp[i-1]，正序；如果依赖 dp[i+1]，倒序
   
5. 画一个简单的例子在纸上走一遍
   → 用 dp 表验证转移方程是否正确
```

**什么时候是 DP 而不是贪心/回溯？** 满足两个条件：**最优子结构**（大问题的最优解包含子问题的最优解）+ **重叠子问题**（不同递归路径重复求解相同子问题）。如果子问题不重叠，回溯就够了；如果每一步的局部最优就等于全局最优，贪心就够了。

## 二、0-1 背包

### 2.1 模型

```
问题: N 个物品，每个物品重量 wt[i]，价值 val[i]。背包容量 W。
     每个物品只能选一次（0-1），求最大价值。

dp[i][w] = 考虑前 i 个物品，容量为 w 时的最大价值

转移方程:
  dp[i][w] = max(
      dp[i-1][w],                          // 不选第 i 个物品
      dp[i-1][w - wt[i]] + val[i]          // 选第 i 个物品（前提 w >= wt[i]）
  )
```

### 2.2 滚动数组降维——为什么内层必须倒序

```java
// 二维 → 一维降维优化
public int knapsack(int[] wt, int[] val, int W) {
    int[] dp = new int[W + 1];
    
    for (int i = 0; i < wt.length; i++) {
        for (int w = W; w >= wt[i]; w--) {     // ← 倒序遍历
            dp[w] = Math.max(dp[w], dp[w - wt[i]] + val[i]);
        }
    }
    return dp[W];
}
```

**为什么内层必须倒序？** 0-1 背包限制每个物品只能用一次。如果正序遍历：

```
w = wt[i] 时更新了 dp[w - wt[i]]，等到推更大的 w 时，
dp[w - wt[i]] 可能已经包含了第 i 个物品 → 物品被用了多次 → 变完全背包
```

倒序遍历保证推 dp[w] 时，dp[w - wt[i]] 还没有被第 i 个物品更新过——它存的还是"前 i-1 个物品"的旧值。

### 2.3 Python 实现

```python
def can_partition(nums):
    """分割等和子集——0-1 背包的变体：
       能不能选出一些数，使它们的和 = sum/2 ?
       dp[w] = 容量 w 能否被刚好填满
    """
    total = sum(nums)
    if total % 2 != 0:
        return False
    
    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True
    
    for num in nums:
        for w in range(target, num - 1, -1):
            dp[w] = dp[w] or dp[w - num]
    
    return dp[target]
```

### 2.4 实际场景

- **CDN 缓存淘汰**：有限缓存空间，每个文件的"大小-价值"不同，选哪些文件缓存价值最大 → 0-1 背包
- **广告位竞价**：每个广告位有展示概率和预期收益，预算有限 → 0-1 背包选择
- **测试用例选择**：有限时间内选哪些测试用例覆盖最多代码 → 0-1 背包

## 三、完全背包

### 3.1 模型

```
与 0-1 背包的唯一区别: 每个物品可以选无限次

转移方程:
  dp[i][w] = max(
      dp[i-1][w],                    // 不选第 i 个
      dp[i][w - wt[i]] + val[i]      // 选第 i 个（注意是 dp[i][...] 不是 dp[i-1][...]！）
  )
  
  ↑ 关键差异：0-1 背包是 dp[i-1][w-wt[i]]（不能再用同一个物品）
             完全背包是 dp[i][w-wt[i]]   （可以继续用同一个物品）
```

### 3.2 一维降维——正序

```java
public int coinChange(int[] coins, int amount) {
    // dp[a] = 凑出金额 a 的最小硬币数
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);     // 初始化为不可能的大值
    dp[0] = 0;
    
    for (int coin : coins) {
        for (int a = coin; a <= amount; a++) {  // ← 正序遍历！
            dp[a] = Math.min(dp[a], dp[a - coin] + 1);
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];
}
```

**完全背包内层正序**：推 `dp[a]`时，`dp[a-coin]` 可能已经用过了第 i 个硬币——允许多次使用。这与 0-1 背包的倒序形成完美对称。

### 3.3 Python 实现

```python
def coin_change(coins, amount):
    """零钱兑换——完全背包"""
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    
    for coin in coins:
        for a in range(coin, amount + 1):
            dp[a] = min(dp[a], dp[a - coin] + 1)
    
    return dp[amount] if dp[amount] != float('inf') else -1

def combination_sum4(nums, target):
    """组合总和 IV：排列数（顺序有关）
       与零钱兑换的关键区别：外层遍历容量，内层遍历物品
       → 不同的遍历顺序 = 不同的语义
        外层物品内层容量 = 组合（无关顺序）
        外层容量内层物品 = 排列（有关顺序）
    """
    dp = [0] * (target + 1)
    dp[0] = 1
    for t in range(1, target + 1):          # 外层容量
        for num in nums:                     # 内层物品
            if t >= num:
                dp[t] += dp[t - num]
    return dp[target]
```

**遍历顺序决定语义**——组合数（(1,2) 和 (2,1) 算一种）→ 外层物品、内层容量；排列数（(1,2) 和 (2,1) 算两种）→ 外层容量、内层物品。面试中的"零钱兑换 II"考的就是这个区分。

## 四、LIS——最长递增子序列（O(n log n) 贪心+二分）

### 4.1 从 O(n²) DP 到 O(n log n)

```
DP O(n²):
  dp[i] = 以 nums[i] 结尾的 LIS 长度
  dp[i] = max(dp[j] + 1) for j < i and nums[j] < nums[i]
  
贪心+二分 O(n log n):
  维护 tail 数组: tail[k] = 所有长度为 k+1 的递增子序列中，最小的结尾元素
  
  对于每个 num:
    在 tail 中二分找第一个 >= num 的位置
    → 找到: 替换该位置（更新更小的结尾值，为后续留更大空间）
    → 没找到: append 到末尾（扩展 LIS 长度）
```

**贪心的直觉理解**：相同长度的递增子序列，"结尾越小越好"——因为结尾越小，后面能接上的数就越多。比如 `[2,5]` 和 `[2,3]` 都是长度 2 的递增子序列，`3 < 5`，所以 `[2,3]` 更"有前途"。

### 4.2 Java 实现

```java
public int lengthOfLIS(int[] nums) {
    // tail[k] = 长度为 k+1 的 LIS 的最小结尾元素
    int[] tail = new int[nums.length];
    int len = 0;
    
    for (int num : nums) {
        // 在 tail[0..len-1] 中二分找第一个 >= num 的位置
        int l = 0, r = len;
        while (l < r) {
            int mid = l + (r - l) / 2;
            if (tail[mid] < num) l = mid + 1;
            else r = mid;
        }
        tail[l] = num;
        if (l == len) len++;   // num 比所有 tail 都大 → 扩展
    }
    return len;
}
```

### 4.3 Python 实现

```python
import bisect

def length_of_lis(nums):
    tail = []
    for num in nums:
        idx = bisect.bisect_left(tail, num)
        if idx == len(tail):
            tail.append(num)
        else:
            tail[idx] = num
    return len(tail)

# 如果需要输出具体序列——还得用 O(n²) DP 回溯
```

LIS 的 O(n log n) 解法本质是**贪心 + 二分**——贪心选择更小的结尾，二分快速定位插入位置。这跟 DP 思维走了完全不同的路径：不是"枚举所有子问题"，而是"巧妙维护一个单调性结构"。

## 五、LCS 与编辑距离——字符串 DP

### 5.1 LCS 最长公共子序列

```
dp[i][j] = text1 前 i 个字符 与 text2 前 j 个字符的 LCS 长度

转移:
  if text1[i-1] == text2[j-1]:
      dp[i][j] = dp[i-1][j-1] + 1
  else:
      dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

```python
def longest_common_subsequence(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i-1] == text2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    
    return dp[m][n]
```

### 5.2 LCS 的实际应用——diff 算法

`git diff` 和文本比较工具的核心就是 LCS。给定旧文件和新文件，LCS 表示"不需要改的行"。改了哪些 = 全部行 - LCS。

基础的 LCS DP 是 O(mn)，对于 10000 行文件意味着 1 亿次比较——可行但不快。Myers diff 算法将问题转化为"在编辑图中找最短路径"，复杂度 O((M+N)D)，其中 D 是差异数（通常远小于 M+N）。Git 中实际用的就是 Myers 算法。

### 5.3 编辑距离（Levenshtein 距离）

```
dp[i][j] = word1 前 i 个字符 变成 word2 前 j 个字符的最小操作次数
允许操作: 插入、删除、替换

转移:
  if word1[i-1] == word2[j-1]:
      dp[i][j] = dp[i-1][j-1]                          // 相同，不需要操作
  else:
      dp[i][j] = 1 + min(
          dp[i-1][j],      // 删除 word1[i-1]
          dp[i][j-1],      // 插入 word2[j-1]（在 word1 当前位置插入）
          dp[i-1][j-1]     // 替换 word1[i-1] → word2[j-1]
      )
```

```python
def min_distance(word1, word2):
    m, n = len(word1), len(word2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    
    # base case: 空串变成 j 个字符 = j 次插入
    for i in range(m + 1): dp[i][0] = i
    for j in range(n + 1): dp[0][j] = j
    
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if word1[i-1] == word2[j-1]:
                dp[i][j] = dp[i-1][j-1]
            else:
                dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
    
    return dp[m][n]
```

### 5.4 实际场景

- **ES 模糊搜索 (fuzziness)**：`fuzziness: AUTO` 基于编辑距离（Damerau-Levenshtein）做拼写纠错
- **拼写检查**：输入 "recieve" → 跟字典中每个词算编辑距离 → 返回距离最小的几个作为建议
- **DNA 序列比对**：Needleman-Wunsch 算法——带权重的 LCS/编辑距离变体
- **推荐系统协同过滤**：两个用户的"购买序列"的相似度 → LCS 长度 / 平均序列长度

## 六、区间 DP——戳气球

区间 DP 的特征：`dp[i][j]` 表示区间 [i, j] 上的最优解，答案在 `dp[0][n-1]`。转移方程是**枚举区间内的分割点 k**。

```python
def max_coins(nums):
    """戳气球——区间 DP 经典
       dp[i][j] = 戳破区间 (i,j) 内所有气球的最高得分
       在 (i,j) 内枚举 k 作为最后一个戳破的
    """
    nums = [1] + [x for x in nums if x > 0] + [1]
    n = len(nums)
    dp = [[0] * n for _ in range(n)]
    
    # 区间长度从小到大（DP 的依赖：小区间推大区间）
    for length in range(2, n):
        for i in range(n - length):
            j = i + length
            # 枚举区间内最后一个戳破的气球 k
            for k in range(i + 1, j):
                dp[i][j] = max(dp[i][j],
                    dp[i][k] + dp[k][j] + nums[i] * nums[k] * nums[j])
    
    return dp[0][n-1]
```

**区间 DP 的遍历顺序**：由于 `dp[i][j]` 依赖 `dp[i][k]` 和 `dp[k][j]`（`i < k < j`），必须从短的区间遍历到长的区间。外层循环是 length，内层是起点 i。错误的遍历——先遍历 i 再遍历 j——会造成用未计算的值推算已计算的值。

## 七、DP 的工程局限——什么时候不该用 DP

- **状态空间爆炸**：背包容量如果以 KB 计（dp 数组数百万维），O(nW) 不可接受 → 近似算法或贪心
- **不满足最优子结构**：某些问题"局部最优"无法组合成"全局最优"——如最长简单路径（无重复节点）没有最优子结构
- **依赖缓存更新时效**：实时系统中 DP 缓存需要在数据变化时重新计算（如推荐系统的相似度矩阵），增量更新代价高

---

DP 不是"背题"，是"学会把一个问题的解，表达为更小的同一个问题的解的组合"。五步法中的第一步（定义 dp 含义）做对了，后面的推导水到渠成。如果第一步卡住——回到问题描述中找**可变参数**，每个可变参数就是 dp 的一个维度。
